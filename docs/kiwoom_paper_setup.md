# 키움 모의투자 조회 연결 가이드

현재 운영 범위는 키움 REST API 모의투자 환경의 인증, 계좌·시세 조회, S80 후보 동기화 및 안전장치가 적용된 모의 주문입니다. 주문 기능은 대시보드와 자동화 모드에 연결되어 있지만 Kill Switch가 기본 활성화되고 자동화 기본값이 `OFF`이므로 명시적인 해제와 승인이 없으면 신규 주문은 차단됩니다.

## 1. 키움에서 준비할 항목

1. 키움증권 계좌와 HTS ID를 준비합니다.
2. [키움 REST API 포털](https://openapi.kiwoom.com/main/home)에서 API 서비스를 신청합니다.
3. 모의투자를 별도로 신청합니다.
4. `모의투자 App Key 관리`에서 사용할 PC의 공인 IP를 등록합니다.
5. 모의투자용 App Key와 App Secret을 내려받아 안전하게 보관합니다.

실전용과 모의투자용 키는 서로 다릅니다. 이 프로젝트에는 반드시 모의투자용 키만 입력합니다. App Key와 App Secret은 다운로드 기회가 제한될 수 있으므로 원본 파일을 안전한 개인 저장소에 보관합니다.

- [공식 서비스 이용안내](https://openapi.kiwoom.com/intro/serviceInfo)
- [공식 모의투자 안내](https://openapi.kiwoom.com/intro/mockInvestInfo)

## 2. 로컬 환경 설정

프로젝트 루트의 `.env`에 다음 두 항목을 추가합니다.

```dotenv
KIWOOM_PAPER_APP_KEY=모의투자용_App_Key
KIWOOM_PAPER_APP_SECRET=모의투자용_App_Secret
```

주의사항:

- 실전용 키를 입력하지 않습니다.
- 키를 채팅, 화면 캡처, 로그 또는 Git에 남기지 않습니다.
- `.env.example`에는 실제 값을 입력하지 않습니다.
- 계좌번호는 설정할 필요가 없습니다. 키움에서 App Key에 등록한 모의계좌를 사용합니다.

## 3. 대시보드 실행과 동기화

```powershell
python -m tools.kis_dashboard_server
```

브라우저에서 `http://127.0.0.1:8765`를 열고 다음 순서로 확인합니다.

1. `키움 모의투자` 탭을 선택합니다.
2. `키움 모의계좌 동기화`를 누릅니다.
3. 연결 상태, 주문 가능금액, 평가금액과 보유 종목을 확인합니다.

정상 조회 후 예상 상태:

- 키움 연결: `연결됨`
- 잔고 동기화: `정상`
- 신규 주문: Kill Switch가 활성화되어 있으면 `차단`
- Kill Switch: `활성`
- 자동화 모드: `OFF`

초기 상태에서 Kill Switch와 자동화 `OFF`는 정상입니다. 주문은 운영자가 Kill Switch를 해제하고 intent를 승인하거나, 정확한 확인 문구로 자동화 모드를 활성화한 경우에만 별도의 주문 전 안전 검사를 거쳐 제출됩니다.

## 4. 현재 적용된 안전장치

- 기본 도메인은 `https://mockapi.kiwoom.com`으로 고정됩니다.
- 실전 도메인 `https://api.kiwoom.com`을 전달하면 클라이언트 생성 자체가 실패합니다.
- OAuth 토큰은 메모리에만 보관하며 대시보드 상태 파일에 기록하지 않습니다.
- 허용된 조회 TR은 접근토큰 발급 `au10001`, 주식기본정보 `ka10001`, 예수금 `kt00001`, 주문·체결 상세 `kt00007`, 평가잔고 `kt00018`뿐입니다.
- 평가잔고는 `KRX`로만 조회합니다.
- 상태 파일에 계좌번호, App Secret 또는 토큰 필드가 들어오면 게시를 거부합니다.
- 모의투자 TR별 초당 1회 제한을 지킵니다.

## 5. 오류 확인

| 표시 코드 | 확인할 사항 |
|---|---|
| `PAPER_CREDENTIALS_MISSING` | `.env`의 모의 App Key와 App Secret 존재 여부 |
| `PAPER_AUTH_FAILED` | 모의 키인지, 키가 정확한지, API 신청 상태인지 확인 |
| `PAPER_AUTH_TRANSPORT_ERROR` | 인터넷 연결, 방화벽 및 키움 서비스 상태 확인 |
| `PAPER_ACCOUNT_READ_FAILED` | 모의계좌 등록과 API 응답 메시지 확인 |
| `PAPER_DASHBOARD_INVALID` | 상태 스키마 또는 민감정보 포함 여부 확인 |

## S80 모의 자동화 모드

대시보드의 자동화 모드는 기본적으로 `OFF`이며, 상태 파일이 없거나 손상돼도
항상 `OFF`로 복구됩니다.

| 모드 | 동작 | 정확한 활성화 확인 문구 |
|---|---|---|
| `OFF` | 자동 조회와 자동 주문을 실행하지 않음 | 없음 |
| `SHADOW` | 계좌·후보·청산 신호만 주기적으로 동기화 | `ENABLE_PAPER_SHADOW` |
| `AUTO_BUY` | 10:00까지 S80 진입 가능 후보를 한 주기당 1주 자동 매수 | `ENABLE_PAPER_AUTO_BUY` |
| `AUTO_TRADE` | 청산 신호를 우선 처리하고 이후 진입 가능 후보를 자동 매수 | `ENABLE_PAPER_AUTO_TRADE` |

`AUTO_BUY`와 `AUTO_TRADE`는 모드 확인 문구 외에도 Kill Switch가 해제되어야
작동합니다. 주문 전마다 모의계좌, 보유·당일 주문, 최대 7종목, 시가 갭 ±3%,
정규장, 최신 가격, 위험 한도 및 저널 무결성을 다시 확인합니다. 한 자동화
주기에는 주문을 하나만 제출하며 결과가 불확실하면 Kill Switch를 즉시
활성화합니다. S80 주문 저널에서 소유권이 확인되지 않는 포지션은 자동 매도하지
않습니다.

모의투자 매수 풀에는 정식 `SELECTED` 선정군을 먼저 배정하고 남은 최대 7종목
한도 안에서 `OBSERVATION` 후보군도 포함합니다. 후보군 주문은
`V1.3-S80-OBSERVATION-PAPER`로 별도 저널링하여 정식 선정군 성과와 섞이지
않도록 합니다. 두 그룹 모두 동일한 갭·중복주문·보유한도·익절·손절·최대
보유기간 안전 규칙을 적용합니다.

평일 08:30~15:20 사이에는 모의투자 동기화에 앞서 직전 거래일의 S80
`PASS` 결과가 있는지 확인합니다. 결과가 없으면 S80 선정을 자동 실행하고,
실패하면 5분 뒤 재시도합니다. 선정 결과 없음, 오래된 기준일, `FAIL` 또는
전략 버전 불일치 상태에서는 `S80_SELECTION_NOT_READY`로 후보와 주문을
차단합니다. 대시보드 서버는 한 포트에 하나만 실행되며 종료 시 요청 처리
스레드도 함께 종료됩니다.

키움 접근토큰은 공식 안내상 24시간 유효합니다. 프로그램은 만료 전에 새 토큰을 발급하며, 토큰 값을 파일이나 화면에 표시하지 않습니다.

## 6. 다음 개발 단계

계좌 조회, 실제 비주문 연결, 직전 거래일 S80 자동 선행 선정, 장중 `SHADOW` 동기화, 주문번호 역조회, 잠긴 모의 주문 전송 계약과 주문 조정기 통합 경계까지 검증했습니다. 대시보드에는 기본 활성 Kill Switch와 intent별 승인·거부 제어 API가 있으며, Kill Switch를 다시 활성화하면 모든 승인이 폐기됩니다. 저장된 승인은 주문 조정자의 제출 준비 단계에서 한 번만 소비되고 감사 이벤트로 기록됩니다. 다음 단계는 명시적 승인 아래 1주 모의 주문 파일럿을 수행한 뒤 부분체결·취소·응답 유실을 검증하는 것입니다. 실전 주문 도메인은 이 과정에 포함하지 않습니다.
